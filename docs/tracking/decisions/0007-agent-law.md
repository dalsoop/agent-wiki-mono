# 0007. 새 공유 원장 agent-law 를 ledger 3 형식으로 열고, 옛 원장은 전신으로 보관한다

## 맥락

2026-10-03~04 사용자와의 설계 대화에서 정했다. 이 결정은 결정 0003(전송)과 0004(기본 world)를 대체한다.

- 지금 객체는 누구의 관점에서 쓴 무엇인지 구분하지 않는다. 사용자 지시, 에이전트 추론, 외부 자료가 모두 같은 객체다. 기억을 정리하는 드리밍이 이것을 섞으면 사용자 원문이 에이전트 추론으로 덮인다.
- 어떤 모델이 썼는지가 거의 남지 않는다(2026-10-03 실측: `gujo-wiki` 객체 2,789건 중 모델 기록 256건). 저작 훅은 등록되어 있지 않았고, 훅은 `runtime` 자리에 세션 시작 출처(`startup`·`clear`)를 넣었다.
- 판결 번호가 저장소마다 임시 번호·순번·MR 번호로 갈라져 있다.
- 세션 대화 전체가 어디에도 보존되지 않는다.
- `gujo-wiki` 의 git origin 은 퇴역한 내부 GitLab 을 가리키고, 객체를 커밋하는 코드가 이 저장소에 없다.
- 객체 id 는 필드 이름·순서로 계산되므로(결정 0001), 필드 이름을 바꾸면 기존 id 가 모두 깨진다.

## 결정

- 새 형식 ledger 3 의 원장 셋(`agent-law` 공유, `agent-law-person-yun-jeonghan`, `agent-law-tenant-gujo`)을 연다. 옛 원장(`gujo-wiki`, `person-yun-jeonghan`, `tenant-gujo`)은 각자의 **전신**이 되어 조회·인용만 되고 쓰기는 막힌다. 옛 원장 객체는 바꾸지 않는다.
- 저장·명령 이름은 법률 어휘(영어)로 바꾼다: 공포 `enact`, 개정 `amends`, 폐지 `repeals`, 현행, 연혁, 증거물 `exhibit`, 사실인정 `finding`, 원상회복 `restore`, 감사 `audit`, 전신 `predecessor`, 가림 `redact`. 옛 명령 이름은 바로 폐지한다(종료 코드 64).
- 관점은 다섯 축으로 나눈다. 작성자·화자·공포일은 기계가 기록하고, 대상·확실성·현실 기간은 별도의 사실인정 기록에 둔다. Claude 의 기억 4종류는 저장하지 않고 축에서 계산한다.
- 모델·추론 강도·실행 도구·버전을 기록 코어(id 계산)에 넣는다. 모델을 모르는 에이전트 기록은 받지 않는다. 신빙성은 측정만 하고 자동 가중치로 쓰지 않는다.
- 원장 정본은 git(gitlab.com `gujoai/agents/agent-law`, 원장별 폴더)이고 공포할 때마다 커밋한다. 모든 기기가 push 한다(0003 의 pull-only 피어를 대체).
- 세션 대화 전체를 R2 전용 버킷 `agent-law` 에 원장 키·기기·실행 도구별로 적재하고, 증인처럼 소환한다. 가림은 증거물에만 하는 유일한 삭제 예외다.
- 심급제: 1심 드리밍, 항소심 다른 모델의 중재자, 대법원 사용자. 규칙 완화와 확정 판결 변경은 대법원에서만 된다.
- 판결 번호는 판결 등록 기록 id 의 앞 8자리다.
- 전역 CLI 의 기본 원장은 `agent-law` 다(0004 를 대체).

## 상용·선행 사례 비교

- **Claude Code 기억:** 사람이 쓴 지시(CLAUDE.md)와 에이전트가 스스로 쓴 관찰을 나누고, 종류를 사람·지적·진행·위치 넷으로 둔다. 자동 드림은 24시간과 세션 5개를 기준으로 돌고 목차를 200줄 안으로 정리한다. → 4종류와 목차를 가져오되, 종류는 축에서 계산한다.
- **Managed Agents 기억 저장소:** 바뀌지 않는 판을 남기고, 비밀이 들어가면 내용만 지우는 가림을 둔다. → 증거물 가림.
- **FactBank:** 같은 사건도 누가 보기에 사실인지가 다르므로 화자와 확실성을 따로 적는다. → 화자·확실성 축.
- **Zep/Graphiti:** 현실에서 참인 기간과 원장에 들어온 시각을 나눈다. → 시행·실효와 공포일.
- **Mem0:** ADD/UPDATE/DELETE/NOOP 로 정리하지만 화자를 구분하지 않고, 최근 판은 에이전트 말도 같은 무게로 둔다. → 따르지 않는다. 사용자 원문은 증언 확인으로만 인정하고 드리밍이 폐지하지 못한다.
- **나무위키 기본방침 개정:** 구체적 개정안, 공지, 이의 제기 기간, 중재자, 운영사 최종 승인. **위키백과 중재위원회:** 분쟁의 마지막 단계이지만 입법부가 아니다. → 심급제와 대법원 공지·이의 기간.
- **옆 저장소 seo-monitor 의 R2 계약:** 덧붙이기만, 같은 주소 재쓰기 실패, 불변 키 앞부분으로 테넌트 구분, 실행 요약은 마지막. → 세션 적재.

## 다른 길

- **옛 원장의 필드 이름만 바꾸기:** 기존 id 가 모두 깨진다(0001). 택하지 않았다.
- **R2 를 원장 정본으로:** 사용자가 원장 정본은 git 으로 두고, R2 는 세션 대화 적재에 쓰기로 했다.
- **세션 적재를 세션 보관 앱(agent-session-archiver)이 맡기:** 가림·테넌트 격리·소환 규칙이 원장 규칙과 두 앱에 나뉜다. 위키가 맡고, 그 앱은 로컬 요약만 한다.
- **드리밍 결과도 증거로 쓰기:** 요약 위에 요약이 쌓여 성능이 떨어진다는 연구("Useful Memories Become Faulty")가 있어, 정리본은 재료·증거에서 뺀다.
