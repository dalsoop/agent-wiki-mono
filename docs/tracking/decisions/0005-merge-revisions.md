# 0005. 갈라진 개정은 병합 개정 하나로 합친다(`supersedes-also`)

## 맥락

2026-09-30 `gujo-wiki` 에서 같은 객체(1c0237c0)를 두 에이전트가 따로 개정해 head 가 둘이 됐다. `supersedes` 는 부모 하나만
담을 수 있어서, 두 본문을 합친 개정도 한쪽만 대체하고 다른 쪽은 head 로 남았다. 내용이 틀린 것이 아니라서 `retracts` 로
지우는 것은 뜻에 맞지 않는다(팀 리드 판단: "git 병합 커밋이 부모를 둘 가지는 것처럼").

## 결정

- 개정 하나가 여러 head 를 대체할 수 있다. 주 부모는 지금처럼 `supersedes:` 한 줄이고, 나머지 부모는 `supersedes-also:`
  줄(부모마다 한 줄)이다. CLI 는 `publish --supersedes <id>` 를 반복해서 받는다(첫째가 주 부모).
- head·분류 승격·참조 검사·그래프 간선은 둘을 모두 본다(`LedgerObject.allSupersedes`, 인덱스 `supersedes_edges` 표).
- `history` 는 주 계보를 따라가다 병합 개정을 만나면 병합된 갈래의 계보를 들여 써서 함께 보인다.

## 대안

- `supersedes:` 줄을 반복: git 과 가장 닮았지만, 옛 판 CLI 파서는 같은 키를 마지막 값으로 덮어써 코어를 다르게
  재계산한다. 다른 Mac 의 옛 CLI 가 병합 개정을 "코어 변조"로 보고하게 된다.
- `retracts` 로 한쪽 철회: 내용이 틀렸다는 뜻이 되어 기록이 왜곡된다.

## 결과

- `supersedes-also:` 줄은 코어의 맨 뒤(모르는 필드 자리 앞)에 들어간다. 옛 판 파서는 이 줄을 모르는 필드로 같은 순서
  그대로 보존하므로 같은 id 를 재계산한다. 부모가 하나인 객체는 줄이 늘지 않아 기존 id 가 바뀌지 않는다.
- 옛 판 CLI 에서는 병합된 부모가 head 로 계속 보일 수 있다(verify 는 통과한다). 새 판으로 올리면 사라진다.
- 인덱스 스키마는 user_version 4 에서 `supersedes_edges` 를 만들고 기존 주 부모로 채운다.
